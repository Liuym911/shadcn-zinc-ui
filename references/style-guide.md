# Shadcn Zinc 后台界面风格规范

本规范可单独提供给 AI，用于构建或改造 shadcn/ui Zinc 中性灰风格的前端界面。沿用目标项目的内容、框架与业务逻辑；明确指定的品牌、主题或布局优先于这里的默认值。

## 视觉方向

整体接近 shadcn/ui 官网的克制后台风格：黑白中性灰、清晰层级、细边框、小圆角和适当留白。数据页面保持紧凑，不为装饰牺牲信息密度。

- 主按钮黑白反色，次操作 outline，导航及轻量操作 ghost，危险操作 destructive。
- 核心数字突出，辅助文字收敛，通过字号、字重和间距体现层级。
- 常规面板使用 1px 边框和轻微阴影，弹窗阴影稍强。
- 图标采用 Lucide 风格线性图标，通常 16px，工具栏可用 18px。品牌图标与通用操作图标分别处理。
- 不添加无任务意义的彩色渐变、大面积发光、营销式巨大标题或过度圆润的卡片。

## 主题色值

使用语义变量，而不是在组件中散落色值。以下是这套风格的固定参考值，不是对 shadcn 官网实时默认值的描述。

| --- | --- | --- |
| `--background` | `#ffffff` | `#09090b` |
| `--foreground` | `#09090b` | `#fafafa` |
| `--card` | `#ffffff` | `#101012` |
| `--card-foreground` | `#09090b` | `#fafafa` |
| `--popover` | `#ffffff` | `#18181b` |
| `--popover-foreground` | `#09090b` | `#fafafa` |
| `--primary` | `#18181b` | `#fafafa` |
| `--primary-foreground` | `#fafafa` | `#18181b` |
| `--secondary` | `#f4f4f5` | `#27272a` |
| `--secondary-foreground` | `#18181b` | `#fafafa` |
| `--muted` | `#f4f4f5` | `#18181b` |
| `--muted-foreground` | `#66666f` | `#a1a1aa` |
| `--accent` | `#f4f4f5` | `#27272a` |

新项目未指定时默认浅色；已有项目保留当前主题、切换入口与持久化方式。选择 `.dark` 或根元素 `data-theme` 一种主机制，确保组件、图表和弹窗同步切换。

## 字体与尺寸

优先本地托管 **Geist Variable**，例如 `@fontsource-variable/geist`。中文回退到 PingFang SC / Microsoft YaHei；受限环境可用系统字体，不强制外部字体 CDN。

| 元素 | 默认规范 |
| --- | --- |
| 页面标题 | 30px，字重 600–650，行高约 1.15，字距约 -0.045em |
| 区块标题 | 15px，字重 600，紧凑字距 |
| 导航、正文、密集表格 | 13px；普通非密集表单可用 14px |
| 辅助文字 | 11–12px；10px 仅用于少量 eyebrow，不承载重要风险信息 |
| 指标数值 | 26px，字重 600，等宽数字；手机约 21–23px |
| 控件高度 | 常规约 36px；紧凑工具栏 32–34px |
| 控件 / 卡片 / 弹窗圆角 | 6px / 10px / 12px |
| 卡片内边距 | 常规 20px；手机 16px |
| 卡片间距 | 14–16px；手机约 10px |
| 页面横向内边距 | 桌面约 32–44px；手机 14–16px |
| 标题到主体 | 约 28px，避免额外叠加过大底部 padding |
| 内容最大宽度 | 常规后台 1600px；高密度工作台可按信息布局全宽 |
| 表格纵向 padding | 常规约 13px；高密度场景按可读性缩减 |

数字使用 `font-variant-numeric: tabular-nums`，金额、价格、单位和精度清晰对齐。中文字号和行高需要实际预览，不机械照搬英文排版。

组件圆角不要直接依赖 shadcn 的通用默认值。配套 CSS 提供 `rounded-control`（6px）、`rounded-card`（10px）和 `rounded-dialog`（12px）；也可显式写相同像素值。通用 `rounded-xl` 在这套 `--radius` 下是 14px，不代表本规范的卡片或弹窗尺寸。

## 组件与布局

React 项目按需使用可维护的 shadcn 源组件，如 Button、Input、Card、Badge、Table、Dialog、DropdownMenu、Tabs 和 Select。

- **按钮**：明确主次、加载和禁用状态。标题加说明的选项使用自动高度、允许换行与左对齐，不让说明溢出点击区域。
- **输入框**：边框清晰、焦点 ring 可见、占位文字较弱。带单位输入保持内部对齐，不改变金额精度与限制。
- **指标卡片**：标签、数值、说明三个层次。桌面通常四列，按宽度降为三列/两列；数量不能整行时按内容跨列，不添加虚假指标凑数。
- **表格**：列头较弱、数据清晰，hover 轻微灰底。宽表在自身容器横向滚动，页面不横向溢出。父层已控制滚动时，适配 Table，避免增加第二层包装。
- **导航**：活跃项用灰底与前景色，不将每个菜单都做成彩色强调。现有项目保留导航组织，样式迁移不自动意味着重排路由。
- **弹窗**：保留标题、简明说明、确认和取消。支持键盘、Esc、焦点约束及关闭后的焦点恢复。
- **图表**：使用同主题的中性网格和轴标签；数据系列颜色独立处理，同一指标在图表与其他区域保持一致。

多行菜单选项可采用以下模式，导入路径按项目调整：

```tsx
<Button
  type="button"
  variant="ghost"
  className="h-auto w-full justify-start whitespace-normal px-3 py-2 text-left"
  onClick={onSelect}
>
  <span className="grid gap-1">
    <span className="text-sm font-medium">选项名称</span>
    <span className="text-xs text-muted-foreground">允许换行的简短说明</span>
  </span>
</Button>
```

这里的 `type="button"` 适用于菜单操作；已有提交按钮应保留提交语义。

## 迁移兼容与可读性

先确认 reset、CSS layer 和路由选择器。新项目使用标准 Tailwind/shadcn 初始化；旧项目依赖旧 reset 时，可先仅引入 Tailwind theme/utilities，暂不启用 Preflight。这种兼容方案不是所有新项目的要求。

共享组件保留事件、refs、原生表单语义、可访问名称及禁用状态。样式调整应保留接口与既有业务行为。

按语义 token 迁移颜色，不批量灰化所有色值。品牌、错误、警告、成功状态和图表序列分别处理。小号正文与实际背景对比度至少 4.5:1，深色文字不要误用 `#71717a`；徽章背景和悬浮状态也需检查。

业务状态的前景与背景立即切换，可保留阴影和焦点反馈，避免同步颜色渐变经过不可读的中间色。

## 验证与交付

检查深浅主题及桌面、约 390px 手机宽度，覆盖长中文/英文、单位数字、空/加载/错误状态、多行菜单和宽表。检查点击区域、表单提交、禁用状态、焦点和弹窗关闭。按项目运行构建、相关测试和可访问性检查。

交付实际预览或截图，注明是否使用合成数据及是否已部署。不仅修改一个样式文件就宣称完成组件迁移，也不为纯展示要求添加不必要的业务模块。
